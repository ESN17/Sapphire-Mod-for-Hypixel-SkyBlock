# 译名库自动更新

客户端默认在每次游戏启动完成后，后台检查 `http://sapphire.esn17cabin.club/translate`。当前该站点尚未部署；在线连接失败不会影响本地翻译。

## 客户端行为

- 完整库命名为 `YYYYMMDD_编号.zip`，先比较日期，再按数字比较编号。例如 `20261030_10.zip` 比 `20261030_2.zip` 新。不降级，不重复下载同版本。
- 第一次启用同步没有远端版本记录，即使内容与内置词典相同，也会下载首个包并校验。以后以安装成功后的版本记录为准。
- 下载、解压、JSON 校验和翻译索引构建在后台串行执行。显示继续使用旧索引，完成后切换到新索引并清空显示缓存。
- 加入 Hypixel 时检查结果未完成，则等待完成再提示。每次连接只自动提示一次，不会向其他玩家发送聊天。
- 已是最新版或更新成功：`译名库已更新至最新版！`
- 连接失败：`暂时无法连接到译名库服务器，请检查防火墙设置或检查是否可以正常登录至译名库服务器！`
- 包损坏、版本不符、缺文件或数据不合法：`译名库更新失败，已保留原有译名库。`
- `/sapphire` 中可关闭“译名库自动更新”；`/sapphire update` 可手动重试，`/sapphire status` 可查看状态。
- `config/sapphire/config.json` 的 `dictionaryUpdateUrl` 可修改检查地址，`dictionaryAutoUpdate` 默认 `true`。不需要玩家登录更新站，也没有客户端上传功能。

## 包格式及保护范围

`exports/dictionaries/20261030_1.zip` 包含全部 `src/main/resources/defaults/translations/**/*.json` 和必要许可证说明。它不含运行目录、Minecraft 账号、API 密钥、用户设置或 NEU 英文元数据。

ZIP 根目录：

```text
sapphire-dictionary.json
translations/*.json
translations/items/*.json
translations/community-wiki/*.json
licenses/LICENSE.txt
licenses/THIRD_PARTY_NOTICES.md
licenses/NEU-LICENSE.txt
licenses/skyzh-LICENSE.txt
licenses/wiki-NOTICE.txt
```

清单标明 `schemaVersion: 1`、`kind: "full"`、版本和每个文件的 SHA-256。发布工具自动生成，不要直接把随意一组 JSON 压缩后上传。

客户端限制压缩包 64 MiB、总解压内容 128 MiB、单个文件 8 MiB、清单 2 MiB、文件数 20,000。拒绝目录穿越、额外文件、重名/大小写冲突、缺文件、重复 JSON 键、超深 JSON 和无法加载的规则。

更新会整体替换 `config/sapphire/translations`。手动修改也包含在被替换的旧库中，旧库保存在 `config/sapphire/dictionary-sync/backups/<事务编号>/translations`，不会静默丢弃。用户配置及密钥文件保持不变。新库的许可证说明保存在同一事务目录的 `installed-licenses`。

已安装版本保存在 `dictionary-sync/state.json`。事务日志在替换前写入，只有替换与版本保存都完成后才删除；中途退出时，下次启动先恢复旧库。成功安装远端完整库后，不再由内置安装器覆盖或补回旧版翻译文件。不要手动更改版本记录冒充更新成功。

目前使用用户指定的 HTTP；SHA-256 能发现损坏，但不能防止传输途中同时被替换的索引与文件。服务上线时建议启用 HTTPS，再将客户端检查地址改为 HTTPS。

## 发布新的译名库

在工程根目录运行：

```powershell
python tools/package_dictionary.py 20261030_2
```

输出在 `exports/dictionaries`。同名 ZIP 已存在时工具拒绝覆盖，应增加编号。上传新 ZIP 和校验文件，最后原子替换 `index.json` / `index.html`，避免索引先公布尚未上传完成的版本。

索引示例（大小和 SHA-256 由工具生成）：

```json
{
  "schemaVersion": 1,
  "files": [
    {"name": "20261030_1.zip", "sha256": "填写工具生成的64位SHA256", "size": 12863036}
  ]
}
```

检查地址既可以返回上述 JSON，也可以返回含同目录 ZIP 链接的普通 HTML。推荐 JSON，以便下载前获得整包校验值与大小。页面中的跨站链接、父目录链接和带查询参数的链接不会被作为发布包。

## Linux 静态站点部署草案（历史参考）

2026-10-31：实际服务器已改为带 HTTPS、账号管理和授权上传的发布站。当前配置、路径和测试结果见 [server/README.md](../server/README.md)；以下静态配置仅为早期方案，不应用来覆盖现有站点。

无需先开发数据库或上传管理后台，就可以分发官方译名库。先把 `sapphire.esn17cabin.club` 的 DNS A/AAAA 记录指向服务器，然后建立独立虚拟主机；现有 `www.esn17cabin.club` 主站无需改动。

以下为 Nginx 配置示例，实际路径及启用方法需按服务器环境调整，尚未在用户服务器执行：

```nginx
server {
    listen 80;
    server_name sapphire.esn17cabin.club;
    root /var/www/sapphire;

    location = /translate { return 301 /translate/; }
    location /translate/ {
        index index.json index.html;
        try_files $uri $uri/ =404;
        add_header Cache-Control "no-cache" always;
        limit_except GET HEAD { deny all; }
    }
    location / { return 404; }
}
```

把 `exports/dictionaries` 的内容上传到 `/var/www/sapphire/translate/`，运行 `nginx -t` 通过后再重载 Nginx。访问 `/translate/` 应返回索引，访问 `/translate/20261030_1.zip` 应能下载 ZIP。

授权人员的账号密码与上传审核属于以后服务器端管理后台，不应加到 Minecraft 客户端，也不要通过公开目录暴露管理配置。正式部署前需要确认当前网站使用 Nginx、Apache、宝塔或其他面板，以及服务器接入方式。

## 离线验证

自动化测试会启动仅监听 `127.0.0.1` 的临时 HTTP 服务，将 ZIP 下载到独立测试目录，校验所有安装后的 JSON，并检查再次启动不会重复下载。不写入真实 `run/config/sapphire`。

```powershell
$env:SAPPHIRE_DICTIONARY_ZIP='D:/Sapphire-source/exports/dictionaries/20261030_1.zip'
.\gradlew.bat build -x jar -x sourcesJar --no-daemon --offline
```

完整包验证结果：`build/dictionary-offline-verification.json`。常规测试还覆盖数字版本排序、连接失败、非法包拒绝、断电式中断恢复、通知时机以及 HTTP 目录重定向。

2026-10-30 验证：完整包共 8,982 个翻译 JSON、8,937 个物品，ZIP 大小 12,863,036 字节；本机 HTTP 安装及逐文件哈希核对约 16.6 秒，重复检查没有再次下载。517 项测试中 515 项通过、2 项可选审计跳过，无失败。干净隔离目录的 Minecraft 26.3 启动、Mixin 审计及真实物品提示测试通过；日志为 `build/dictionary-sync-verified.log`。尚未进行正式更新站与 Hypixel 在线联调。

如要手动在开发客户端验证，可从 `exports/dictionaries` 启动本机静态服务，临时把检查地址改为 `http://127.0.0.1:8000`，然后使用 `/sapphire update`。验证结束恢复默认检查地址；不要把本机地址写入发布用默认配置。
