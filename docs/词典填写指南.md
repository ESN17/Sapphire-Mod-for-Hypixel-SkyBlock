# Sapphire 词典填写指南

你只需要填写 JSON 的中文字段，不需要修改 Java。所有文件使用 UTF-8、英文双引号，不支持注释和尾随逗号。空值表示待翻译，运行时保留英文。

## 先填写哪里

`dictionary-workspace/translations/` 是供你编辑的独立目录，不会自动影响游戏。里面的英文名称、ID 和 Lore 由官方 NEU 数据生成。`examples/translations/` 中的旧示例保留原样。

正式游戏读取的是**该启动器实例**的 `config/sapphire/translations/`。开发客户端读取 `run/config/sapphire/translations/`。不要把文件放进资源包目录。

当前快照已有全量中文，可挑选常用物品继续审校。空词条仍表示保留原文；不要为了通过校验而猜测未知文本。

## 每个物品一个 JSON

文件示例：`translations/items/ASPECT_OF_THE_END.json`。

```json
{
  "schemaVersion": 1,
  "id": "ASPECT_OF_THE_END",
  "_original_name": "Aspect of the End",
  "_original_lore": ["Damage: +100", "This item can be reforged!"],
  "name": "末影之刃",
  "lore": {
    "Damage: +100": "",
    "This item can be reforged!": "此物品可以洗练!"
  }
}
```

- `id`、`_original_name`、`_original_lore`：英文参考，不要改。生成器会自动填写。
- `name`：填写中文基础名称，不添加洗练前缀、等级或星级；显示层保留这些部分。
- `lore`：左边是完整英文行，右边填写中文。空行可以省略，暂时不会翻译的行保留 `""`。
- 颜色和样式来自原始组件，不需要手填 `§`。私人使用的字体符号（如 ``）和特殊图标应保留。
- 没有 NEU 索引时，`_original_name` 必须填写准确，否则名称保守回退英文。旧示例没有该字段时，请手动补充或生成 NEU 索引。

ID 取自 SkyBlock 元数据，不由名称猜测。宠物使用 NEU 的 `TYPE;RARITY`，单附魔书使用 `ENCHANTMENT;LEVEL`。无法可靠识别的变体不强行套用翻译。

## 通用词条与模板

`translations/global.json` 是完整文本精确匹配：

```json
{
  "Damage": "伤害",
  "Strength": "力量",
  "This item can be reforged!": "此物品可以洗练!",
  "RARE SWORD": "稀有 剑"
}
```

它不做任意子字符串替换。`Damage` 不会匹配 `Damage: +100`。

数值变化的行写到 `translations/templates.json`：

```json
{
  "Damage: {value}": "伤害：{value}",
  "Strength: {value}": "力量：{value}",
  "Mana Cost: {value}": "魔力消耗：{value}",
  "Purse: {value} Coins": "钱袋：{value} 硬币",
  "Cooldown: {time}": "冷却时间：{time}"
}
```

`{value}`、`{amount}`、`{value1}` 等普通变量匹配整数、小数、正负号、千位分隔符和百分号。`{time}` 支持 `1:30`、`10s`、`1h 20m`。`{name}`、`{text}`、`{prefix}`、`{suffix}` 匹配最长 128 字符的非空单行文本，只用于你已确定上下文的翻译模板；不要把用户名、URL 或命令作为翻译目标。

中文必须保留相同变量名，可调整顺序。源模板不能重复同名变量，不能把两个变量直接连在一起。全行匹配、英文常量更长的模板优先。可选前后缀可写成多条明确模板；物品名称的外部前后缀则自动保留。

全量生成的描述使用 `{{N0}}`、`{{N1}}` 等双大括号数字占位符。必须原样保留括号形式、名称和出现次数；不要改成 `{N0}`，也不要填入固定数字。旧的 `{value}` 等具名模板继续兼容。

执行用户标准：Dungeon=地牢、Uncommon=罕见、Reforge=洗练、Magic Find=稀有物品概率加成。完整标准见 `tools/translation_policy.json`；Kat 等 NPC 名称保留英文。译文标点沿用英文源文本的半角风格，数字正负号、百分号和字体图标保持不变。

优先级：物品专属完整行 → 当前类别完整行 → global 完整行 → templates → 原文。聊天只使用 chat 精确匹配，不套用通用模板。

## 菜单与其他文本

以下文件均为同样的“完整英文 → 中文”对象：

| 文件 | 内容 |
| --- | --- |
| `gui.json` | 容器菜单标题和经过词典确认的菜单项 |
| `chat.json` | 确认属于系统的完整聊天消息；不放玩家聊天 |
| `scoreboard.json` | 右侧计分板文字 |

```json
{
  "Bazaar": "集市",
  "Auction House": "拍卖行",
  "Manage Orders": "管理订单"
}
```

## Windows 工具命令

在项目目录打开 PowerShell，安装 Python 3.10 或更新版本后运行。把路径替换成你的实际游戏实例路径。`--root` 必须放在子命令前。

```powershell
python tools/dictionary_tool.py --root dictionary-workspace validate
python tools/dictionary_tool.py --root "D:/Games/Minecraft/config/sapphire" merge dictionary-workspace
python tools/dictionary_tool.py --root "D:/Games/Minecraft/config/sapphire" sync "D:/NEU-Repo"
```

主动从官方 GitHub 同步（需要 Git 和网络）：

```powershell
python tools/dictionary_tool.py --root dictionary-workspace sync --github
```

同步只生成缺失的物品词典，**不改已有中文文件**。英文最新参考更新到 `neu-index.json`，新增/变化/移除/错误清单在 `neu-sync-report.json`。已有 `_original_lore` 可能因此是旧参考，校对时以最新索引和变化清单为准。NEU 的许可证另存为 `NEU-LICENSE.txt`，再分发索引时一并保留。

`validate` 报错含文件名、JSON 路径或解析位置。空翻译、没有中文名称、ID 不在 NEU 中属于待审核警告；加 `--strict` 可以把警告视为失败。

## 游玩收集 → 填写 → 导入

1. 进入 Hypixel SkyBlock，执行 `/sapphire status` 确认 `SkyBlock=true`。
2. 执行 `/sapphire untranslated on`。默认关闭收集；普通游玩时每秒扫描当前物品栏/容器，悬停时也检查 Tooltip。
3. 执行 `/sapphire untranslated export`，或者正常退出游戏，让后台记录保存。
4. 在 PowerShell 导出一个**新的**文件名（不会覆盖之前填写的导出文件）：

```powershell
python tools/dictionary_tool.py --root "D:/Games/Minecraft/config/sapphire" stats
python tools/dictionary_tool.py --root "D:/Games/Minecraft/config/sapphire" scan --category item --id ASPECT_OF_THE_END
python tools/dictionary_tool.py --root "D:/Games/Minecraft/config/sapphire" export "D:/translation-batch-01.json"
```

5. 在导出文件的 `entries` 里填写 `name` 和 `lore` 右侧中文，其他字段保留。
6. 导入并校验：

```powershell
python tools/dictionary_tool.py --root "D:/Games/Minecraft/config/sapphire" import "D:/translation-batch-01.json"
python tools/dictionary_tool.py --root "D:/Games/Minecraft/config/sapphire" validate
```

7. 回游戏执行 `/sapphire reload`，无需重新构建 Mod。

导入只补充空值和新词条，已有非空中文冲突会列出并保留旧译文。若想修改已有译文，请直接编辑正式词典后重载。无可靠 ID 的物品不会自动导入，需要人工核实；不会通过名称猜 ID。

`_candidates` 是动态数值模板的候选样本，仅供审核。工具不会自动把候选提升为正式模板；审核后手工加入 `templates.json`。完成的记录再次出现时仍保留你已写入的中文字段。

## 收集范围与隐私

收集器不把“包含英文字母”当作未翻译证据。物品文本只接受 NEU 原文和 `collection-rules.json` 中审核过的规则；无法确定的原始名称不会落盘。聊天必须是服务器系统入口且匹配你明确配置的安全规则，默认没有聊天收集规则。前缀 `[NPC]` 不是来源证明。

收集规则只允许完整固定文本及数值/时间变量，禁止任意名称/文本变量。未知消息会被排除，因此初始版本不会自动抓取所有新 NPC 对话或所有菜单。

记录包括分类、上下文、ID、状态、时间、采样出现次数、英文样本和人工填写区。每个键最多每秒观察一次；出现次数是采样次数，不是渲染帧数。动态值归一化只用来去重和提出候选。达到文件/磁盘上限后停止新增写入，并在 `/sapphire untranslated` 显示原因。

`/sapphire untranslated off` 停止接收新记录，之前已排队的记录仍可保存。`/sapphire untranslated clear` 关闭收集并清除本工具生成的本地记录。请先导出已填写的数据。

## 格式保留策略

变量片段保留自己的颜色、粗体、事件和数字；名称前后缀保持原状。普通译文继承原句一致的有效样式。多色句通过 `styleMappings` 标注语义对应；无法确定对应关系时保留英文。装饰性彩虹单词可明确映射整个词，并将原调色板应用到中文字符，这一规则不用于普通多色句。

`showOriginal=true` 会保留原文供对照，描述原文放在译文后面的独立行。新配置默认 `forceTranslation=true`，环境检测为 false 时仍显示词典中的译文；可用 `/sapphire force off` 恢复仅在确认 SkyBlock 后翻译。总开关和分类开关仍然有效，强制翻译**不能绕过收集的 SkyBlock 环境门槛**。

## 段落、动态数值与颜色对应

物品 JSON 支持 `loreParagraphs` 和 `styleMappings`，无需按英文换行填写中文。末影之刃的完整示例位于 `dictionary-workspace/translations/items/ASPECT_OF_THE_END.json`。

```json
{
  "loreParagraphs": [
    {
      "source": [
        "Teleport {distance} blocks ahead of you and",
        "gain {speed}  Speed for {duration} seconds."
      ],
      "translation": "向前传送 {distance} 格,并获得 {speed}  速度,持续 {duration} 秒."
    }
  ],
  "styleMappings": {
    "blocks": "格",
    "Speed": "速度",
    "seconds": "秒",
    "RIGHT CLICK": "右键点击"
  }
}
```

将这些字段加入原物品对象，与 `name`、`lore` 并列；以上仅为字段示例，不是完整物品文件。

- `source` 按实际连续英文行填写，不能跨越空行。中文 `translation` 填写整段，游戏按字体实际宽度重新换行，空白分段和其他提示行保留。
- `{distance}`、`{speed}`、`{duration}` 从实际物品文字提取，保留数值、正负号和颜色。无需列举 8、9、10、11、12 格；调谐器、魔力消耗变化均读取实际描述，不由 Mod 计算属性。
- `lore` 也支持数字模板，例如 `"Mana Cost: {value}": "魔力消耗：{value}"`。同一物品的精确非空词条优先于该物品模板，物品模板优先于通用词典。源与译文的占位符必须一致，不要删除或改名。
- `styleMappings` 是英文片段与中文片段的对应关系，不是固定色号。例如原文 `blocks` 绿色时，“格”复制绿色；原文 `RIGHT CLICK` 黄色粗体时，“右键点击”复制黄色粗体。
- 每个 `loreParagraphs` 条目可以有独立的 `styleMappings`，优先于物品级映射，避免名称和不同描述中的同词相互干扰。没有该字段的旧段落继续使用物品级映射。
- 单色说明可以映射完整动态模板，例如 `"(Max {{N1}} stacks)": "(上限 {{N1}} 层)"`。两侧必须保留相同占位符，原说明内部必须同一完整样式。普通属性数值仍优先直接复制；不要单独添加 `"{{N0}}": "{{N0}}"`。
- 不变且可唯一定位的数字、图标和括号自动复制原样式。重复数值请用不同占位符标识，避免只靠数字内容定位。重复图标仅在两侧数量相同、原文各次出现的完整样式一致时自动复制；样式不同则保留原文。宝石槽可用 `"Gemstones: {text}": "宝石槽：{text}"` 整体保留括号和图标样式。
- 不要手写 `§` 颜色码来修复分段；颜色、粗体、斜体、下划线、删除线、字体与交互信息从原组件复制。一个映射片段内部必须样式一致，并且在该次原文和译文中可唯一定位。较长词组优先，例如先匹配 `Crit Damage`，再匹配未被覆盖的 `Damage`。非包含式重叠、歧义或未映射的多色文本会保留原文，不猜测位置。
- 数字后的 `s`、`m`、`x` 可在 `styleMappings` 中分别对应“秒”“分钟”“倍”，复制原单位的颜色。若译文里同一个字出现多次，请补充更长的语义对应，如 `"per second": "每秒"`，避免与后面的持续时间“秒”混淆。
- `loreParagraphs` 的空译文与旧 `lore` 的空值一样表示待翻译，不表示隐藏原文。

段落字段、样式对应和洗练词典均已纳入 `dictionary_tool.py validate` / `merge`。合并不会覆盖已有非空译文。首次使用这些功能需要更新 Mod 或重启开发客户端；之后只改词典可执行 `/sapphire reload`。

洗练前缀单独填写在 `translations/reforges.json`，例如 `"Heroic": "英雄的"`。完整中英名称及统计口径见 [洗练词典说明](重铸词典说明.md)。

宠物名称也可以使用 NEU 的等级占位符，例如 `"name": "[等级 {LVL}] 末影人"`，并在 `styleMappings` 中添加 `"Enderman": "末影人"`，使名称沿用宠物稀有度颜色，等级沿用原等级颜色。`_original_name` 保留 `[Lvl {LVL}] Enderman`。宠物名称后面的皮肤/装饰符号会原样保留。

现有完整示例还有：`RECOMBOBULATOR_3000.json`（重组器 3000）、`DRAGON_SCALE.json`（龙鳞）、`PET_ITEM_QUICK_CLAW.json`（迅捷利爪）、`ENDERMAN;0.json` 至 `ENDERMAN;5.json`（普通到神话的末影人）。NEU 参考数据中的 `{0}` 等是 NEU 自身的参数标记；实际匹配模板使用 `{reduction}` 等具名数字占位符，具体写法见这些文件。
