# Sapphire 用户称号

## 客户端行为

开启「Sapphire 用户称号」后，每次连接 Hypixel 会在后台通过 HTTPS 获取称号名册。只提交当前 Minecraft 用户名，不提交密码、登录令牌、聊天内容或其他玩家名单。

登记规则：

1. 每次登录先获取服务器名册；已有用户名无需再次上传。
2. 名册尚无记录且本机没有成功登记回执时，提交一次用户名。
3. 收到成功回执后立即写入 `config/sapphire/rank-registration.json`，即使后续下载失败，也不重复上传。
4. 登记失败不会记录为成功，下次登录可以重试。用户名变化时，新用户名单独登记一次。
5. 本机已登记但服务器停用该名字时，不自动重新启用；由授权人员管理。
6. 已在线的 Hypixel 客户端每 60 秒仅下载一次名册，以显示新登记用户；周期刷新不会调用登记接口。历史聊天行保留当时的显示，之后收到的聊天使用最新称号。

公开名册缓存位于 `config/sapphire/rank-roster.json`，与翻译词典分离。服务不可用时保留缓存，不阻塞游戏。请求仅发生在后台线程；Tab 和玩家头顶名称使用最多 256 项的显示缓存。

本功能只改客户端渲染副本，覆盖 Tab、玩家头顶名称、聊天整段文本（含公会名单、系统通知及正文提及的已登记用户名），以及经过统一显示钩子的界面文本。普通用户显示深蓝色 `#0000AA` 的 `[SAPPHIRE]` 和亮白色 `#FFFFFF` 用户名。`ESN17_OwO` 与 `BoostingDetected` 显示整体亮红色 `#FF5555` 的 `[SAPPDEV] 用户名`。名字前的 SkyBlock 等级及 Tab 个人信息中的等级数值同步使用用户名颜色；经验进度、在线状态圆点、频道和其他文字保留原色。不会改服务器段位、GameProfile、聊天签名或服务器原始数据。

匹配以完整文本组件为单位，支持同一段多个名字及跨颜色片段的名字，不再依赖聊天发送者开头或 Tab 底层档案名。只匹配名册内的完整用户名，保留点击/悬停事件；NPC 标签与 URL 内的文字不替换。重复经过显示钩子不会叠加称号。翻译先执行、称号着色后执行，避免称号处理跳过整行汉化。

## 服务器与管理

- `GET https://sapphire.esn17cabin.club/customrank/roster`：公开称号名册。
- `POST https://sapphire.esn17cabin.club/customrank/register`：JSON `{"name":"用户名"}`；相同名字不区分大小写，重复登记不新增、不重置管理配置。
- `/customrank/`：已登录授权人员的管理页，未登录会返回登录页。

首页公开区域已移除称号按钮；登录后显示「管理 Sapphire 用户称号」。授权人员可新增、修改或停用普通用户称号。两名指定开发者的称号与颜色固定。权限、CSRF、输入校验、并发登记和 IP 哈希限流均在服务器端处理。修改名册不授予任何网站管理权限。

此名册记录客户端自报的公开用户名，用于装饰显示，并非 Microsoft 身份验证或“已安装 Mod”的密码学证明；不能作为权限、交易或身份认证依据。不会收集 Minecraft 凭据来证明身份。

数据保存在现有私有 SQLite 的 `ranks` 和 `rank_limits` 表，不在公开站点目录中。部署前已备份数据库、Sapphire 首页及 Nginx 配置，备份位于 `/www/sapphire-deploy/ranks-backup-*`。已有译名库更新接口不受影响。

本次不打包 JAR。既有 dev 0.0.5 无同步版不包含此功能，需之后明确要求打包新版本才能分发给玩家。
